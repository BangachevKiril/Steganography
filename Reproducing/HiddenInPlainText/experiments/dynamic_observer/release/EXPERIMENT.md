# Dynamic university observer sweep

Authorized settings k=0,1,2,4,8; 200 complete cycles each, each with 2 full DistilBERT updates, 5 Gemma LoRA PPO updates, then k observer LoRA updates. All runs use the same verified original checkpoint zero, disjoint sender/receiver training halves, and observer seed. The separate Qwen3-4B PIQA judge remains frozen for every k.

Reward: 2*p_R(correct)-1 -(2*p_O(good)-1)^2 +0.1*min(character_count/20,1). No threshold, raw-logit reward, or filtering. PPO KL remains separate. Receiver CE uses 256 samples in four microbatches of 64. Sender batch192/minibatch64/accumulation3 and learning rate1.41e-5 are retained. Receiver shuffle wraps the end of its half to produce exactly256 unfiltered samples; sender retains drop_last.

Observer: same pinned Qwen3.5-27B-FP8 checkpoint revision97f5941bf617e31c5e237364a8602ce3f03a551a, explicitly dequantized to BF16 for supported autograd, not FP8 execution parity. Identical BF16 computation and zero-initialized LoRA B for k0 and trainable cases. Rank16/alpha16/dropout0.05 FP32 adapters on all text-model linear layers except LM head; frozen base and vision weights; AdamW lr2e-5/wd0.01, gradient clipping1.0, batch256 with microbatch1, nonreentrant gradient checkpointing. Binary CE uses normalized Bad/Good logits, not full-vocabulary language-model CE. Label token IDs must be verified as single-token continuations.

Observer data are the current cycle's 2*256+5*192=1472 training summaries. Each observer step samples256 without replacement from this pool, independently between steps, with an isolated deterministic selection RNG. Pool and all three optimizers/adapters/RNG/streams/PPO state are saved in an atomic joint checkpoint. k0 has no observer optimizer or backward passes and adapter identity is checked. Evaluation uses all2000 university examples and100PIQA at cycle0, every10completecycles, and cycle200; it runs after observer updates and records receiver accuracy, observer accuracy/confidence and PIQA rejection. No held-out rows enter SFT.

H100/H200 validation uses a real full cycle at k1, batch256 receiver,192 sender,256observer, mini evaluation64university/4PIQA and checkpoint restoration. Production is gated on matching source/spec/hardware validation and performs its own full initial evaluation. Observer weights temporarily move to CPU during sender PPO; the previously audited layout-preserving saved-tensor CPU offload is retained. Neither numerical parity across precisions nor GPU fit is claimed until measured. Preemptions resume only this run's latest complete joint checkpoint.
